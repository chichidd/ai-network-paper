\subsection{\red{Detector Retraining and Adaptation}}

\red{Federated learning coordinates parameter updates while keeping raw
records at their owners, which suits settings in which participants retain
training data and can run another optimization process
~\cite{federated_learning,Fedprox,ditto2021}. Within intrusion detection,
federated methods adapt this process to non-IID traffic and heterogeneous
local learners~\cite{pourahmadi2023fedoe,xu2026entente}. Other recent NIDS
methods retrain or adapt detectors to cope with scarce labels, traffic change,
or noisy annotations; CoLD, for example, filters unreliable annotations before
model fitting~\cite{qing2024rapier,xie2023rosetta,yang2026cold}. These methods
address important deployment conditions, but all include detector training or
adaptation in the collaboration. Our setting begins after the contributed
detectors have been trained and their historical records are no longer
available.}

\subsection{\red{Pretrained Model Integration}}

\red{When source records disappear but their trained models remain accessible,
pretrained-model integration provides the closest starting point. Existing
approaches either rank a heterogeneous model zoo on current target data
~\cite{dong2022zood} or combine pretrained models without accessing their
source records~\cite{wei2024tgr,zhao2024modelglue}. They do not select one fixed
detector subset under a hard aggregate budget while treating class support as
a strict priority.}

\subsection{\red{Output-Level Ensembles and Cost-Aware Selection}}

\red{Once model outputs are available, stacked generalization can train a
downstream classifier over them~\cite{wolpert1992stacked}. In security, SIRAJ
learns a common representation from heterogeneous malicious-entity detectors
~\cite{thirumuruganathan2022siraj}, while Fed-MStacking trains a global
meta-classifier from heterogeneous local predictions in a missing-label
setting~\cite{qiu2024fedmstacking}. A separate line studies cost-aware
inference: SPIREL learns a per-item policy that trades off model invocations
and classification utility~\cite{birman2022spirel}. These approaches either
combine outputs or control per-item cost, but they do not screen detectors and
return one fixed subset under a hard aggregate budget. \Fname makes this
subset decision before fitting one shared classifier over the selected
outputs.}

\subsection{\red{Local Privacy for Prediction Uploads}}

\red{Prediction outputs can reveal information about their inputs, so a
privacy guarantee must identify both where randomization occurs and which
fields it covers. PrivateKT perturbs locally produced predictions before
sending them for knowledge transfer~\cite{qi2023privatekt}. Differentially
private federated trees instead protect statistics exchanged while training a
new model~\cite{dpfedtree_ccs22}. Because \Fname uploads selected detector
scores to fit a shared classifier while treating labels as public, we
specialize the local model of Duchi et al.~\cite{duchi2013localprivacy} to this
release.}

{\color{red}
\begin{definition}[Label-conditional local differential privacy]
\label{def:local_dp}
For a fixed public label $y$, a client applies a randomized mechanism
$\mathcal M_y$ to the feature vector $x$. The upload
$\mathcal R(x,y)=(\mathcal M_y(x),y)$ satisfies label-conditional
$(\epsilon,0)$-local differential privacy if, for every fixed $y$, every pair
$x,x'$, and every measurable output set $\mathcal O$,
\begin{equation}
\Pr[\mathcal M_y(x)\in\mathcal O]
\le e^{\epsilon}\Pr[\mathcal M_y(x')\in\mathcal O].
\label{eq:local_dp_definition}
\end{equation}
The definition therefore compares records with the same public label and
protects only the randomized, feature-derived output.
\end{definition}
}

\red{To instantiate Definition~\ref{def:local_dp}, let a deterministic score
map $g$ have replacement sensitivity
\begin{equation}
\Delta_1(g)=\sup_{x,x'}\lVert g(x)-g(x')\rVert_1.
\label{eq:local_l1_sensitivity}
\end{equation}
Adding independent noise
$\eta_k\sim\operatorname{Lap}(0,\Delta_1(g)/\epsilon)$ to every coordinate
satisfies Definition~\ref{def:local_dp}~\cite{dwork2006calibrating}. If one
record releases blocks with parameters $\epsilon_1,\ldots,\epsilon_s$,
sequential composition gives parameter $\sum_{i=1}^{s}\epsilon_i$. Under
one-record replacement, releases derived from unchanged records do not add to
this privacy parameter.}

\red{In \Fname, this mechanism applies only to the selected detector-score
blocks. Theorem~\ref{thm:local_score_privacy} therefore proves
label-conditional local privacy for the score upload; it does not protect
calibration, labels, detector parameters, or the complete protocol.}
